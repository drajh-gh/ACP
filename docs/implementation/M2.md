# M2 — Codex counterpart and workers

- Status: In progress
- Baseline: uncommitted candidate based on `main` at
  `1370b5fbee7066ef0757d07d00833ce77fe9a810`
- Specification: [1.0.0](../../SPECIFICATION.md)

## Implemented

- [x] Add bounded, versioned, canonical-digest context packets with exact
      mission, node, project, role, capability, evidence, previous-result,
      lifecycle, output-schema, and resource-limit identity.
- [x] Add bounded, versioned, supervisor-digested worker results and reject
      run/context mismatches, cross-run claims or effects, and malformed output.
- [x] Persist immutable capability evaluations and their exact expiring grants;
      pin resource class in policy evaluation/grant, and consume attempts only
      through admitted worker runs.
- [x] Implement a worker manager that revalidates the exact packet and grant,
      applies a role-specific tool manifest and isolation descriptor, enforces
      a bounded deadline, and persists structured terminal outcomes.
- [x] Pin `@openai/codex-sdk` `0.153.3` and start a fresh thread for each run,
      with no authoritative conversation history or resume identifier.
- [x] Configure non-delivery workers with the SDK's read-only sandbox and no
      network, approvals, additional directories, or effect-executor access.
- [x] Pass a minimal OS environment to the Codex subprocess so control-plane,
      GitHub, deployment, and other service secrets are not inherited.
- [x] Configure delivery workers for workspace-write only inside a
      Git-plumbing-verified linked worktree boundary, with no effect credentials;
      an ordinary checkout or fabricated pointer pair fails closed.
- [x] Require a full Git object ID from successful delivery results and compare
      it independently with the isolated worktree's actual `HEAD`.
- [x] Demonstrate synthetic replacement from a new packet containing only the
      prior run's typed result reference, not conversation history.
- [x] Persist worker hosts, database-timed heartbeats, TTL freshness, host kind,
      state, and per-resource-class capacity; reject new runs on stale, offline,
      draining, missing, or saturated hosts.
- [x] Bind each manager to one immutable local host identity rather than
      accepting a caller-selected execution-host label.
- [x] Add typed host registration, heartbeat, and capacity-ranked availability
      queries that exclude the operator laptop unless explicitly requested.
- [x] Add immutable worker-process journaling schema and prevent a run, node, or
      mission from becoming terminal while its recorded process is running.
- [x] Add supervisor-facing process registration, heartbeat, exact terminal
      replay, atomic expiring reconciliation claims, stale/deadline selection,
      unjournaled-run detection, and terminal-process/run-projection gap queries.
      These derive run, host, resource class, and deadline identity from durable
      state, bind provenance to the host, and use the database clock.
- [x] Require reconciliation actors to hold a process-keyed PostgreSQL session
      advisory lock while inspecting or terminating the exact PID/start-token
      tuple while that database session remains alive; abort inspection and
      withhold terminal writes on connection loss.
- [x] Persist the supervisor-observed OS process start time separately from the
      database observation time, and reject contradictory exit-code/state pairs.
- [x] Add an authenticated Streamable HTTP MCP endpoint with bearer comparison
      resistant to timing leaks, a one-MiB JSON body limit, exact Host and Origin
      checks, trusted-proxy-only HTTPS forwarding, and plugin-version admission.
- [x] Expose typed `create_mission`, `get_mission_status`, and
      `list_active_missions` MCP tools.
- [x] Make mission creation idempotent by client request ID and semantic digest,
      and bind creation to one exact active project workflow and configured
      runtime-provenance identity in the same database transaction.
- [x] Scaffold and validate the `plugins/codex-counterpart` plugin package,
      including its counterpart skill, tool allowlist, remote MCP configuration,
      bearer-token environment reference, and compatibility header.
- [x] Database-check packet workflow/profile/policy/completion references,
      mission state, evidence hashes/summaries, active claims, approvals, and
      prior-result references against authoritative records at insertion time.
- [x] Publish immutable, sequential node-context revisions with exact graph,
      mission, provenance, bounded intent, and reference-selection identity.
      Concurrent publications use compare-and-swap; identical replay is safe.
- [x] Assemble the current context-packet schema from durable node intent,
      mission scope, pinned profile source rules, references, and independent
      lifecycle observations. Packet/provenance persistence is atomic, and SQL
      recomputes assembly to reject caller-injected content.
- [x] Revalidate the authoritative snapshot at worker admission, serialize with
      mission cancellation/context publication, fence the exact next attempt,
      prevent overlap with live predecessor runs/processes, and prevent
      supplied deadlines exceeding packet limits. Legacy packets
      remain readable but cannot admit new worker runs.
- [x] Add durable, host-aware DBOS dispatch with immutable request identity,
      locked capacity reservations, atomic same-transaction enqueue, and exact
      host/session/resource-class queue affinity. Operator laptops are opt-in.
- [x] Register host configuration and runtime bindings atomically, fence live
      incumbent sessions using their original TTL, and permanently reject
      retired session identifiers. Reassignment uses a new generation and fresh
      packet/provenance IDs; unavailable work does not monopolize a sweep.
- [x] Connect the host consumer to authoritative packet assembly and the worker
      manager. Existing admitted runs require reconciliation or replay their
      terminal result without another transport invocation, including DBOS step
      recovery. Recheck prerequisites at actual run admission.
- [x] Renew host authority independently of queue sweeps, enforce a local TTL
      watchdog during stalled renewal, and bridge exact durable cancellation
      intent into active-worker aborts and new-run admission denial. Draining
      allows existing workers to finish. Shutdown aborts even when database
      closure fails, and late success cannot override cancellation.
- [x] Project terminal worker/node/dispatch results atomically under consistent
      mission-to-node locks. Unstarted admission failures become `needs_input`,
      and resumed preparation clears obsolete completion timestamps.
- [x] Add a Windows 10+/PowerShell 7 supervisor around the trusted SDK runner:
      atomic job ownership at suspended creation, held-handle PID/FILETIME
      identity, whitelisted inherited stdio, and bounded private launch/result IPC.
      Existing Resource Guard restrictions remain inherited.
- [x] Commit exact process/job identity before release and enforce a permanent
      one-supervised-root-per-run fence. Revalidate current mission/node/run,
      cancellation, host/session authority, and actual deadline after waiting
      for admission locks. Preserve legacy journals as history.
- [x] Stop and confirm the whole owned tree before durable process completion
      and result projection. Enforce native deadlines independently of blocked
      input/output, close the tree on daemon/bridge loss, and retain
      reconciliation-required state when termination evidence is unavailable.
- [x] Bound process-journal calls, renew exact process identity, recover a lost
      registration acknowledgement by exact lookup after tree stop, and withhold
      results on uncertain durable completion or a late heartbeat failure.
- [x] Add machine/boot/session-scoped Windows recovery that verifies held
      job/root identity, fails closed on ambiguous namespace or access, and
      confirms tree stop without PID-only killing or inferred success.
- [x] Recover journaled runs after their original daemon session retires or
      explicitly hands off the exact run,
      using bounded keyset sweeps, fresh same-binding runtime provenance, exact
      per-process claims, retained PostgreSQL timestamp precision, and current
      session/host/claim rechecks after locking. Abort and await inspector cleanup
      on shutdown, lease expiry, or database loss.
- [x] Repair stopped-process/run gaps under admission locks, preserve terminal
      winners and cancellation, and prove a real journaled native owner's death
      followed by durable process/run/node recovery without a duplicate launch.
- [x] Evolve context packets to 1.1.0 with lifecycle observation IDs/timestamps,
      exact candidate IDs and revision SHAs, tracker source versions, and explicit
      known/unknown deployment artifact versions (specification 16.1(10)).
      Metadata-only drift invalidates admission; already-admitted 1.0.0 runs keep
      their original packet digest and remain recoverable after upgrade.
- [x] Protect the five lifecycle observation tables against UPDATE, DELETE,
      TRUNCATE, and future-dated insertion, with a locked populated-data migration
      preflight. Producer rollback preserves the audit guards and packet history;
      re-upgrade supports the retained guards without duplicating them.
- [x] Require known artifacts for required deployed/verified completion states,
      support exact artifact-digest conditions, and preserve unknown artifact
      facts for diagnosis without inventing out-of-scope deployment requirements.
- [x] Add a one-way, exact-assignment recovery handoff from a still-current
      manager after its local invocation fails. Abort late transport authority
      before handoff, fence late journal/heartbeat/result writes in PostgreSQL,
      and retain started state and capacity until confirmed process-stop recovery.
      A healthy daemon and its other runs remain active; replay alone cannot
      hand off a healthy owner. Terminal results that win first remain unchanged.
- [x] Retry missing journals and lost handoff acknowledgements by exact identity
      through a bounded, fair local queue. Queue exhaustion fences the daemon
      and stops renewal; a crash falls back to retired-owner recovery. Handoff
      without a journal or stop evidence cannot manufacture a terminal result.
- [x] Preserve immutable handoff identity and independent mission-event receipts.
      Refuse downgrade while any handed-off run remains started, and retain the
      audit receipts after removing the operational handoff table.

## Remaining before M2 completion

- [ ] Deploy the control API behind a real HTTPS URL, replace the plugin's
      reserved `.invalid` endpoint, configure a high-entropy secret outside the
      repository, and prove a real Codex-to-hosted-MCP connection.
- [ ] Publish the plugin through a selected personal or repository marketplace.
      The package validates, but this implementation task did not authorize
      modifying the operator's personal Codex marketplace or choose a team
      marketplace destination.
- [ ] Supply production daemon/bootstrap configuration and a trusted plan/node
      publisher that selects work, provisions grants/templates, and submits
      dispatch requests. The embeddable queue/consumer boundary is implemented;
      deployment and unattended live execution are not claimed.
- [ ] Close the unjournaled launch gap with durable launch-intent authority,
      and establish safe cross-boot/session recovery. Journaled same-scope Windows
      crashes, explicit current-owner handoffs, and terminal-process/run gaps are recoverable;
      missing or ambiguous stop evidence remains pending.
- [ ] Add Linux/systemd supervision and prove production-host orphan cleanup
      and live replacement. Windows synthetic probes now prove owned-tree exit,
      abort, deadline, blocked-pipe handling, and daemon-loss cleanup; they do not
      prove authenticated Codex execution or Linux production-host recovery.
- [ ] Run a live Codex worker against a disposable repository and prove a
      deliberate write attempt is denied by the actual read-only sandbox. Unit
      tests prove the technical SDK configuration and manager capability gates,
      but no authenticated live model run is part of this repository check.
- [ ] Add a durable repository-ID-to-filesystem binding and a renewable lease
      guard held across Git mutation, then provision, persist, and retire real
      isolated worktrees around delivery dispatch. The manager verifies an
      existing boundary but does not create or remove it.
- [ ] Add a restricted tool broker (or equivalent process/container boundary)
      that technically enforces individual operation/resource grants. The SDK
      sandbox enforces filesystem/network posture, while the current
      operation/resource manifest is still conveyed to the model as a contract.
- [ ] Configure a policy-backed restricted-evidence disclosure path. The
      builder currently denies restricted evidence instead of guessing consent.
