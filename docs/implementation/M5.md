# M5 — Console and attention

- Status: In progress; independent local work alongside unfinished M2/M3.
- Specification: [1.0.0](../../SPECIFICATION.md), §§19, 23, 31.1 and M5 milestone.

## Implemented

- [x] Strict bounded recorded attention item contract with all twelve specified
      types, stable project/mission/evidence/effect references and decision-ready
      descriptions, without interpreting them as action permission.
- [x] Exact semantic identity, canonical reference sets, ordered responses and
      alternatives, retained optional-field distinctions and UTC microsecond expiry.
- [x] Bounded queue query/response contracts with deterministic urgency/time/ID
      ordering, exact continuation and explicit recorded-only/freshness/authority
      limits. Expired items are not automatically resolved.
- [x] Durable attributed recording with immutable canonical and request-alias IDs,
      project-key deduplication, exact historical replay and no automatic uncertain
      COMMIT retry or readback.
- [x] Same-project reference enforcement and single-statement whole-page current
      disclosure, including indirect effect evidence, anchor and lookahead rows.
- [x] Authenticated read-only `get_mission_attention` counterpart tool, complete
      structured-payload size checks and source plugin version 0.4.0, preserving
      older default compatibility and explicit operator restrictions.

## Evidence

Thirteen focused domain cases pass after eight initial positive RED cases.
Independent read-only review found no critical domain defect; explicit tests now
cover optional-array presence, alternative order and same-priority time/ID ties.
Nine storage unit cases and 23 actual PostgreSQL checks cover concurrency, actual
lost COMMIT, producer chronology, reference/alias retention, overflow, read-only
access, MVCC disclosure and empty/populated rollback. Review findings have explicit
RED/GREEN regressions. Migration 0022 and the private producer/read projection are
implemented. Eleven HTTP cases and six actual PostgreSQL/HTTP checks verify the
new tool, exact cursor traversal, metadata privacy, SELECT-only access and zero
SQL dispatch for invalid or unauthenticated inputs. Independent review passes the
storage and MCP boundary; the source plugin and skill are locally validated.
Strict TypeScript compilation, all 768 local tests, secret scanning and whitespace
checks pass. Each PostgreSQL phase uses an owned disposable container and bounded
process tree; the six phases run sequentially, never as parallel heavy gates.
See [ADR0037](../architecture/0037-recorded-attention-queue.md).
